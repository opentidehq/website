The `opentide` PyPI package is the SDK as well as the command line. Its entry point is **`opentide.Workspace`**: a Tide workspace, opened once, with everything you do with it as a method. It wraps the [Rust SDK](/docs/sdk/rust/)'s `opentide` crate one to one, compiled into the package, so Python, Rust and the [TypeScript SDK](/docs/sdk/typescript/) run the same code and return the same documents: the command line's `--json` data, with its keys in its order. A conformance suite holds them to it: every operation, on every test workspace, gives the same document through the three SDKs, byte for byte, on Linux, macOS and Windows. The one exception is notation: JavaScript has one number type, so the Node SDK reads a float such as `120.0` in a document as `120`.

```python
from opentide import Workspace, __version__

ws = Workspace.open(".")
validation = ws.validate()
print(__version__, len(ws.rules()), "rules,", validation.summary["objects"], "objects checked")
```

## Public entry points

| Symbol | Purpose |
|--------|---------|
| `opentide.Workspace` | Open a workspace (`open`, `from_files`); `validate`, `lint`, `info`, `rules`, `objectives`, `threats`, `catalog`, `coverage`, `deploy_plan`, `tenants`, `run_json` |
| `opentide.run_json` | Run any `opentide` command in the process and return its `--json` document |
| `opentide.Connection` | One tenant's client (`open`); the `async` tenant operations `query`, `validate_query` and `deploy` |
| `opentide.TenantConfig` | A tenant: what `Workspace.tenants` returns, or one configured in code |
| `opentide.OpentideError` | What a call that cannot run raises, with a stable `code` |
| `opentide.Validation`, `opentide.LintReport`, `opentide.DeployPlan` | What `validate`, `lint` and `deploy_plan` return |
| `opentide.QueryResult`, `opentide.LiveCheck`, `opentide.DeployOutcome`, `opentide.DeployWarning`, `opentide.DeployEvent` | What `query`, `validate_query` and `deploy` return |
| `opentide.Canceller` | What `Connection.canceller()` returns: stops the connection's operations from elsewhere |
| `opentide.Capabilities` | What a platform's connector can do (`deploy`, `live_validation`, `query`): `Connection.capabilities()`, `opentide.sdk.capabilities(platform)` |
| `opentide.sdk.platforms()` | The platforms with a connector, in the order opentide lists them |
| `opentide.models` | The Tide models: `DetectionRule`, `ThreatVector`, `DetectionObjective`, the platform blocks |
| `opentide.plugins` | The plugin API: `PlatformPlugin`, which adds a detection platform |
| `opentide.analysis` | `check_query`: one query checked offline |
| `opentide.__version__` | The package's version |

`import opentide` loads none of them until you use one: it takes about a millisecond, and 30 ms at most.

## Worked example: validate, then plan a deploy

Validate the workspace, stop on an error, and plan what a deploy of the rules in preview would send. Nothing is sent and nothing is written:

```python
from opentide import Workspace

ws = Workspace.open(".")

validation = ws.validate()
for issue in validation.report["issues"]:
    print(f"{issue['path']}:{issue['line']}: {issue['code']}: {issue['message']}")
if validation.failed:
    raise SystemExit(validation.exit_code)

plan = ws.deploy_plan(strategies=["PREVIEW"])
for platform, rules in plan.document["plan"].items():
    print(platform, len(rules), "rules")
print(plan.summary)
```

A real deploy is the command line's: `ws.run_json(["deploy", "--strategy", "RELEASE", "--all"])` runs it in the process and returns its envelope, with [credentials](/docs/usage/configuration/#credentials) set in the environment. To query, check a query live or deploy one rule on a tenant from an `asyncio` application, await a [`Connection`](/docs/sdk/workspace/#tenant-operations)'s methods.

## Choosing between SDK, CLI, and MCP

Use the SDK to embed the engine in Python; use the [CLI](/docs/cli/) for humans and pipelines; use [MCP](/docs/mcp/) for agents. See [Choosing an interface](/docs/usage/choosing-an-interface/).

## Type hints

The package ships `py.typed` (PEP 561) and the stubs of its compiled module (`opentide/_native/*.pyi`); `ty` checks the package with no exclusions. The options are typed with the choices the command line accepts (`queries="warn"`, `strategies=["PREVIEW"]`); the documents are `dict[str, Any]`, with the keys of [JSON output](/docs/cli/json-output/).

## Source layout

```
src/opentide/
├── __init__.py          # Workspace, Connection, run_json, __version__ (loaded on first use)
├── sdk.py               # Workspace, Connection and run_json, over opentide._native.sdk
├── _cli.py              # the `opentide` console script: the Rust command line, in process
├── _native/             # the compiled Rust core and its stubs
├── models/              # the Tide models (Rust classes)
├── plugins.py           # the platform plugin API
├── analysis.py          # check_query, offline
└── data/                # bundled data: configuration defaults, vocabularies, diagnostics pages
```
