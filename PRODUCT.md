# opentide Website

## Register

brand

## Target users

Detection engineers, security platform operators, and AI-agent integrators building detection-as-code repositories across enterprise SIEMs.

## Product purpose

Marketing site and documentation hub for opentide — spec-driven development for agentic detection engineering. Help visitors evaluate the project, install the CLI/SDK/MCP stack, read normative specifications, and adopt spec-driven detection engineering workflows.

## Positioning

opentide is **spec-driven development for agentic detection engineering**: an **ontology** (threat → objective → rule, linked by UUID) and a **taxonomy** (versioned vocabularies) that keep every detection threat-aligned, maintainable and fast to ship, with or without agents. The engine (one package: CLI, SDK, MCP) enforces the spec; your detection repo stays the source of truth.

- Lead with **threat alignment, maintainability, speed and quality**.
- The agent story: agents made the query cheap; the spec keeps their output aligned. Agents go through the same gates as a human change.
- Do **not** frame the product around honesty ("tools that never lie", "honest adapters", "never fake a pass"). State capabilities as plain facts — for example, CrowdStrike and HarfangLab are deploy-only.

## Brand personality

**Coastal precision** — deep EU-blue tides, golden signal highlights, pixel-ocean motion, engineering credibility without corporate sterility. Agent-forward but human-first.

## Anti-references

Generic SaaS gradients, glassmorphism hero cards, identical icon+heading card grids, uppercase tracked eyebrows on every section, gradient text, navy-and-gold fintech clichés.

## Strategic principles

- Inter + JetBrains Mono only; no display font drift
- Pantone Reflex Blue `#001489` (light) and Yellow `#FFCC00` (dark) as committed brand colors (light = white+blue, dark = black+yellow)
- One signature motion: ASCII tide hero (FLIP liquid sim rendered as monospace glyphs); restrained CSS elsewhere
- Landing follows theme: light white+blue, dark black+yellow (same rule as docs)
- Docs sidebar always shows root dropdown; Usage is the default entry
- Accurate platform capability claims: say what deploys and what validates, never more
- Prefer real artefacts (YAML, commands, JSON envelopes) over illustrations
